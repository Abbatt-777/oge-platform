# Техническое задание — платформа подготовки к ОГЭ/ЕГЭ

Дата: 26.09.2026

## 1. Назначение системы

Платформа сопровождает учеников, готовящихся к ОГЭ/ЕГЭ: хранит программы и материалы, ведёт расписание индивидуальных и групповых занятий, собирает документы, принимает оплату и даёт интерактивные задачи по математике.

Видеосвязь платформа не обеспечивает. Занятия проходят на внешних площадках (Яндекс Телемост, Zoom), платформа хранит только ссылку на подключение.

Сознательно вне объёма: собственная видеосвязь, мобильные приложения, автоматический подбор преподавателя, интеграция с бухгалтерией, электронная подпись договоров (договор подписывается от руки и загружается сканом).

## 2. Пользовательские роли

Три роли. Самостоятельной регистрации нет: все аккаунты создаёт администратор.

| Роль | Вход | Что доступно |
| --- | --- | --- |
| Ученик (общий аккаунт ученика и родителя) | Телефон или email + код подтверждения | Своя анкета, свои программы и материалы, своё согласованное расписание, свои документы, свои счета и оплата, интерактивные задачи |
| Преподаватель | Телефон или email + код подтверждения | Своя анкета, своё расписание с согласованием, список своих учеников и групп, свои часы (отработанные и оставшиеся), отметка о проведённом занятии |
| Администратор | Email + пароль | Всё: аккаунты, анкеты, программы, группы, расписания, ссылки на занятия, документы, счета, отчёты по часам |

Преподаватель не видит документы, счета и контактные данные учеников за пределами того, что нужно для занятия (ФИО ученика и состав группы). Ученик не видит других учеников, кроме состава своей группы.

Проверка прав выполняется на сервере при каждом запросе, а не скрытием элементов интерфейса.

## 3. Основной бизнес-процесс

Порядок работы платформы. Каждый шаг меняет состояние объекта, и следующий шаг невозможен, пока предыдущий не завершён.

1. **Администратор создаёт аккаунты** преподавателей и учеников и вносит базовые данные (раздел 4). Пользователь получает приглашение на почту и при первом входе заполняет анкету.
2. **Ученик загружает** скан или фото подписанного договора и согласия на обработку ПДн (раздел 5). Администратор проверяет и подтверждает или отклоняет с указанием причины.
3. **Администратор формирует группы и расписание** — индивидуальных и групповых занятий — и закрепляет за каждым занятием преподавателя (разделы 6 и 7). Расписание уходит в кабинет закреплённого преподавателя со статусом «на согласовании».
4. **Преподаватель согласовывает расписание.** После согласования занятия появляются в кабинете ученика, и ученику уходит письмо с расписанием. Несогласованное занятие ученику не видно.
5. **В день занятия администратор формирует ссылку** на подключение и отправляет её. Ссылка появляется в кабинетах преподавателя и всех участников занятия.

Оплата идёт параллельно процессу: администратор выставляет счёт, ученик оплачивает в своём кабинете (раздел 10).

**Требует подтверждения:** блокирует ли неоплаченный счёт или неподтверждённый договор доступ к занятиям. В текущей редакции — не блокирует, занятия доступны независимо от статуса оплаты и документов; администратор видит задолженность в своей панели и решает вопрос вне платформы.

## 4. Аккаунты и анкеты

Администратор заводит аккаунт и вносит базовые данные. Пользователь дозаполняет анкету сам при первом входе.

### Базовые данные (вносит администратор, обязательны для обеих ролей)

ФИО, дата рождения, телефон, электронная почта, город проживания, роль (ученик или преподаватель).

После сохранения пользователю уходит письмо-приглашение со ссылкой на вход. Вход по коду подтверждения на почту или телефон — пароль не используется, поэтому и восстанавливать нечего.

### Анкета ученика (заполняет сам)

| Поле | Обязательное |
| --- | --- |
| Класс | Да |
| Школа | Нет |
| Предметы подготовки | Да |
| Целевой балл | Нет |
| ФИО родителя или законного представителя | Да |
| Телефон родителя | Да |
| Часовой пояс | Да, по умолчанию московский |
| Удобное время занятий | Нет |

### Анкета преподавателя (заполняет сам)

| Поле | Обязательное |
| --- | --- |
| Преподаваемые предметы | Да |
| Образование (вуз, факультет, год выпуска) | Да |
| Курс обучения, если студент | Нет |
| Опыт преподавания | Нет |
| Часовой пояс | Да, по умолчанию московский |
| Доступные для занятий интервалы времени | Да |

Анкета редактируется пользователем в любой момент; администратор видит её целиком и может править.

Состав анкет — предложение, а не требование из исходного задания: заказчик указал только базовые поля. Перед разработкой состав нужно утвердить, потому что поля анкеты определяют структуру базы данных.

Банковские и платёжные реквизиты преподавателей на платформе не хранятся: выплаты идут вне системы.

## 5. Документы

Два типа документа, обрабатываются одинаково: договор и согласие на обработку персональных данных.

Порядок: администратор публикует шаблон PDF для конкретного ученика → ученик скачивает, подписывает от руки, фотографирует или сканирует, загружает через кабинет → администратор проверяет.

### Статусы документа

| Статус | Что означает | Что видит ученик |
| --- | --- | --- |
| Не загружен | Шаблон опубликован, файл не загружен | Кнопка скачать шаблон и загрузить файл |
| Загружен | Файл получен, ждёт проверки | «Ожидает проверки», файл доступен для просмотра |
| Подтверждён | Администратор принял документ | «Подтверждён», файл доступен для просмотра |
| Отклонён | Администратор отклонил с указанием причины | «Отклонён», текст причины, кнопка загрузить заново |

Статус «Подтверждён» добавлен относительно исходного задания: без него администратор не отличает проверенные документы от ждущих проверки.

При отклонении статус не сбрасывается в «Не загружен» — иначе у ученика молча пропадает файл без объяснения. Сохраняется отдельный статус «Отклонён» с причиной.

### Требования к загружаемым файлам

Допустимые форматы: PDF, JPG, PNG. Максимальный размер одного файла: 10 МБ. При превышении — понятное сообщение с указанием фактического и допустимого размера.

### Доступ к файлам

Загруженные файлы доступны только самому ученику и администратору. Прямая ссылка на файл не должна открываться без авторизации — файлы отдаются по временным ссылкам с ограниченным сроком действия. Преподаватель к документам учеников доступа не имеет.

## 6. Группы и закрепление преподавателей

Платформа поддерживает оба формата: индивидуальные и групповые занятия.

### Группа

Группу создаёт администратор: название, программа, закреплённый преподаватель, предельный размер, состав учеников. Ученик может состоять в нескольких группах одновременно (например, по математике и по русскому языку) и параллельно иметь индивидуальные занятия.

Состав группы администратор меняет в любой момент. Ученик, добавленный в группу, видит только уже согласованные будущие занятия этой группы; прошедшие до его добавления занятия ему не показываются.

### Закрепление преподавателя

Преподаватель закрепляется за группой или за индивидуальной связкой «ученик — программа». Преподаватель может вести несколько групп и несколько индивидуальных учеников.

Замена преподавателя: администратор назначает другого, все ещё не проведённые занятия переходят к нему и требуют его согласования заново. Проведённые занятия остаются в учёте часов прежнего преподавателя.

### Участники занятия

У каждого занятия фиксируется список участников. Для индивидуального занятия это один ученик, для группового — состав группы на момент создания занятия. Список участников определяет, кому занятие видно и кому уходит ссылка на подключение.

## 7. Расписание и согласование преподавателем

Занятие проходит путь от создания администратором до появления в кабинете ученика. Ученик видит занятие только после согласования преподавателем.

### Состояния занятия

| Статус | Кто переводит | Видно ученику |
| --- | --- | --- |
| Черновик | Администратор создал, ещё не отправил | Нет |
| На согласовании | Администратор отправил преподавателю | Нет |
| Согласовано | Преподаватель подтвердил | Да, уходит письмо |
| Отклонено преподавателем | Преподаватель отказался, с комментарием | Нет |
| Ссылка направлена | Администратор добавил ссылку в день занятия | Да, кнопка «Подключиться» |
| Проведено | Преподаватель отметил после занятия | Да, в истории |
| Отменено | Администратор отменил | Да, помечено как отменённое |

### Формирование расписания

Администратор создаёт занятия пакетом: выбирает группу или ученика с программой, преподавателя, задаёт даты и время. Длительность занятия — не более 40 минут (ограничение бесплатного тарифа Zoom, единое правило для всех площадок).

При сохранении система проверяет пересечения: у преподавателя и у каждого участника не должно быть двух занятий в одно время. Пересечение показывается администратору как предупреждение с указанием конфликтующего занятия.

Все даты и время хранятся в UTC и показываются каждому пользователю в его часовом поясе.

### Согласование

Пакет занятий приходит в кабинет преподавателя со статусом «на согласовании». Преподаватель согласовывает пакет целиком одной кнопкой либо отклоняет отдельные занятия, указав причину (например, занят в это время).

Отклонённое занятие возвращается администратору с комментарием преподавателя. Администратор меняет время и отправляет заново.

**Требует подтверждения:** срок на согласование. Предлагается: если преподаватель не отреагировал за 48 часов, занятие подсвечивается администратору как просроченное. Автоматического согласования по истечении срока нет — занятие без явного подтверждения преподавателя ученику не публикуется.

### Публикация ученику

Согласованные занятия появляются в кабинете каждого участника. Одновременно каждому участнику уходит письмо с расписанием: предмет, дата, время в его часовом поясе, длительность, преподаватель, формат (индивидуально или в группе).

## 8. Ссылки на занятия

В день занятия администратор создаёт встречу на внешней площадке вручную и вставляет готовую ссылку в карточку занятия. Платформа не создаёт встречи сама и не проверяет, какой сервис стоит за ссылкой — хранится обычный URL.

Поддерживаемые площадки: Яндекс Телемост и Zoom. Поле «площадка» в карточке занятия нужно только для подсказки в интерфейсе.

После сохранения ссылки занятие переходит в статус «Ссылка направлена», и кнопка «Подключиться» появляется в кабинете преподавателя и в кабинетах всех участников занятия одновременно.

Администратор может заменить ссылку до начала занятия — участники увидят новую при следующем открытии страницы.

**Требует подтверждения:** уходит ли письмо со ссылкой участникам, или ссылка появляется только в кабинете. В текущей редакции письмо со ссылкой уходит, поскольку в день занятия человек может не открывать кабинет заранее.

## 9. Учёт часов преподавателя

Администратор видит по каждому преподавателю плановый объём, отработанные и оставшиеся часы. Преподаватель видит то же самое по себе.

### Плановый объём

Администратор задаёт плановое количество занятий при закреплении преподавателя за группой или индивидуальным учеником. Например, 48 занятий на шестимесячный курс из двух занятий в неделю.

### Как считаются часы

Единица учёта — проведённое занятие. Академические часы получаются пересчётом по длительности:

- Отработано занятий = число занятий в статусе «Проведено»
- Отработано часов = сумма длительностей проведённых занятий ÷ 60
- Осталось занятий = плановое количество − отработано
- Осталось часов = осталось занятий × стандартная длительность ÷ 60

При длительности 40 минут одно занятие даёт 0,67 астрономического часа. Отменённые и отклонённые занятия в отработанные не попадают.

**Требует подтверждения:** в каких единицах вести учёт — в занятиях или в часах, и считать ли групповое занятие так же, как индивидуальное. В текущей редакции групповое занятие засчитывается как одно занятие независимо от числа учеников.

### Отметка о проведённом занятии

После занятия преподаватель отмечает его как проведённое в своём кабинете. Пока отметки нет, занятие в отработанные часы не попадает.

Администратор может поставить или снять отметку сам — например, если преподаватель забыл. Все изменения отметки сохраняются с указанием, кто и когда её изменил.

**Требует подтверждения:** нужна ли отметка посещаемости по каждому ученику группы. В текущей редакции отмечается только факт проведения занятия целиком, без поимённой посещаемости.

## 10. Онлайн-оплата

Ученик оплачивает в своём кабинете счёт, выставленный администратором. Самостоятельно инициировать платёж без счёта ученик не может.

### Порядок

1. Администратор выставляет счёт конкретному ученику: сумма, назначение платежа (например, «Математика ОГЭ, октябрь»), срок оплаты.
2. Счёт появляется в разделе «Оплата» кабинета ученика, ученику уходит письмо.
3. Ученик нажимает «Оплатить» и переходит на страницу платёжного сервиса.
4. После оплаты сервис возвращает ученика в кабинет и отдельно уведомляет платформу о результате.
5. Статус счёта меняется на «Оплачен», администратор видит это в своей панели.

### Статусы счёта

| Статус | Что означает |
| --- | --- |
| Выставлен | Ожидает оплаты |
| Оплачен | Платёж подтверждён платёжным сервисом |
| Просрочен | Срок оплаты прошёл, платежа нет |
| Отменён | Администратор отменил счёт |

История счетов сохраняется и доступна ученику и администратору.

### Требования к платёжной части

Платформа не хранит и не обрабатывает данные банковских карт: ввод реквизитов происходит на стороне платёжного сервиса, платформа получает только результат платежа.

Статус «Оплачен» ставится исключительно по уведомлению от платёжного сервиса на сервер, а не по возврату пользователя на страницу успеха — иначе статус можно подделать простым переходом по ссылке.

Каждый платёж связывается с идентификатором транзакции сервиса, чтобы можно было сверить расхождения.

**Требует решения заказчика:** выбор платёжного сервиса. Подключение онлайн-оплаты требует зарегистрированного юридического лица или ИП, договора с сервисом и, по российскому законодательству, выдачи кассового чека покупателю. Актуальные тарифы и условия конкретных сервисов в этом документе не проверялись — это отдельное решение до начала работ по этому разделу. От выбора сервиса зависит только способ подключения, остальная логика раздела не меняется.

## 11. Материалы и интерактивные задачи

### Программы, темы, материалы

Программа (например, «Математика ОГЭ») состоит из тем, расположенных в заданном порядке. В теме — материалы трёх видов: файл (PDF или документ), ссылка на видео, текст.

Материалы хранятся отдельными записями, а не одним полем: в одну тему можно добавить несколько файлов и ссылок, и порядок их отображения задаётся администратором.

Ученик видит только материалы назначенных ему программ.

### Интерактивные задачи

Задача принадлежит теме. Два типа ответа: числовой или выбор одного варианта из предложенных.

После отправки ответа ученик сразу видит результат — верно или неверно — и текстовое объяснение. Объяснение показывается в обоих случаях, независимо от результата.

Повторные попытки не ограничены. Каждая попытка сохраняется: ответ, результат, дата и время. Историю попыток видят ученик и администратор.

Числовой ответ принимается и с запятой, и с точкой как разделителем дробной части; лишние пробелы отбрасываются.

В первой версии задачи создаются только для программ по математике. Структура данных не ограничивает применение к другим предметам в будущем.

**Требует подтверждения:** видит ли преподаватель историю попыток своих учеников. В текущей редакции не видит — в исходном задании это право закреплено только за администратором. По смыслу работы преподавателю это, вероятно, нужно.

## 12. Административная панель

Рабочее место администратора, рассчитанное на настольный компьютер.

| Раздел | Что в нём |
| --- | --- |
| Ученики | Список, создание аккаунта, базовые данные, анкета, назначенные программы и группы, статусы документов, счета |
| Преподаватели | Список, создание аккаунта, базовые данные, анкета, закреплённые группы и ученики, плановые и отработанные часы |
| Программы | Программы, темы, материалы, интерактивные задачи |
| Группы | Создание групп, состав, закрепление преподавателя |
| Расписание | Формирование занятий пакетом, статусы согласования, добавление ссылок в день занятия, отмена занятий |
| Документы | Публикация шаблонов, проверка загруженных, подтверждение и отклонение с причиной |
| Оплата | Выставление счетов, статусы, история платежей, задолженности |

### Что администратор видит на главной

- Занятия на сегодня и статус ссылок по ним
- Занятия, ожидающие согласования преподавателями, с выделением просроченных
- Документы, ожидающие проверки
- Просроченные счета

### Отчёт по часам преподавателей

Отдельная таблица: преподаватель, закреплённые группы и ученики, плановое количество занятий, проведено, осталось, подтверждённых занятий в расписании на ближайший период. Таблица фильтруется по периоду и выгружается в файл.

Это прямое требование заказчика: администратор должен видеть подтверждённые расписания и количество отработанных и оставшихся часов у каждого преподавателя.

## 13. Уведомления по электронной почте

Канал один — электронная почта. SMS и мессенджеры в объём не входят.

| Событие | Кому |
| --- | --- |
| Создан аккаунт | Приглашение со ссылкой на вход |
| Расписание согласовано преподавателем | Каждому участнику занятия — письмо с расписанием |
| Новый пакет занятий на согласование | Преподавателю |
| Занятие отменено или перенесено | Участникам и преподавателю |
| Ссылка на занятие направлена | Участникам и преподавателю |
| Документ отклонён | Ученику, с указанием причины |
| Документ подтверждён | Ученику |
| Счёт выставлен | Ученику |
| Счёт оплачен | Ученику — подтверждение, администратору — уведомление |

Письмо с расписанием содержит: предмет, дату, время в часовом поясе получателя, длительность, преподавателя, формат занятия.

Обязательное по прямому требованию заказчика — письмо с расписанием после согласования преподавателем. Остальные события предложены по смыслу процесса и требуют подтверждения: лишние письма раздражают, недостающие приводят к пропущенным занятиям.

## 14. Обработка персональных данных

Платформа обрабатывает персональные данные, в том числе данные несовершеннолетних: ФИО, дату рождения, контакты, город, данные родителей, сканы подписанных договоров.

**Важная оговорка.** Ниже перечислены технические требования, которые нужно заложить в разработку. Этот документ не является юридическим заключением: какие именно обязанности возникают у оператора персональных данных в вашем случае, какой должна быть формулировка политики и требуется ли уведомление надзорного органа — должен проверить юрист до запуска платформы. Разработчик реализует механику, а не отвечает за юридическую корректность формулировок.

### Технические требования

- Страница с политикой обработки персональных данных, доступная без авторизации, со ссылкой в подвале всех страниц.
- Отдельный экран согласия при первом входе: пользователь не попадает в кабинет, пока не отметит согласие. Факт согласия сохраняется с датой, временем и версией текста политики.
- Форма согласия на обработку ПДн, подписываемая от руки и загружаемая сканом (раздел 5), — отдельный документ, не заменяющий отметку в интерфейсе.
- Для ученика младше 18 лет согласие даёт родитель или законный представитель; его ФИО и контакт обязательны в анкете ученика (раздел 4).
- Данные хранятся на серверах, размещённых на территории Российской Федерации. Это требование нужно подтвердить у юриста и учесть при выборе хостинга, поскольку оно ограничивает круг доступных площадок.
- Доступ к данным разграничен по ролям (раздел 2). Преподаватель не имеет доступа к документам, счетам и полным контактным данным учеников.
- Файлы документов хранятся в приватном хранилище и отдаются только по временным ссылкам после проверки прав.
- Все действия с документами и данными пользователей записываются в журнал: кто, что и когда изменил.
- Удаление аккаунта и данных по запросу пользователя выполняет администратор; порядок и сроки согласовать с юристом.

### Что нужно подготовить до запуска, помимо разработки

Тексты политики обработки персональных данных, формы согласия и договора; решение о необходимости уведомления надзорного органа; решение по размещению серверов. Всё это вне компетенции разработчика.

## 16. Нефункциональные требования

### Интерфейс

Кабинеты ученика и преподавателя проектируются в первую очередь под телефон: ученики и преподаватели заходят преимущественно с мобильных устройств. Административная панель рассчитана на настольный компьютер.

Используется готовая библиотека UI-компонентов вместо индивидуального дизайна с нуля — это прямая экономия бюджета без потери опрятного вида.

Вёрстка соответствует согласованному макету экранов (кабинет ученика и административная панель).

### Безопасность

- Проверка прав доступа на сервере при каждом запросе к данным, а не скрытием элементов интерфейса.
- Файлы документов недоступны по прямой ссылке без авторизации.
- Ученик не получает доступа к данным других учеников, кроме состава своей группы.
- Преподаватель видит только своих учеников и свои занятия.
- Статус оплаты меняется только по серверному уведомлению платёжного сервиса.

### Инфраструктура

При небольшом числе пользователей на старте сложная масштабируемая инфраструктура не нужна — подойдёт простой недорогой хостинг. Ограничение: размещение серверов должно соответствовать требованиям к хранению персональных данных (раздел 14), это нужно подтвердить до выбора площадки.

### Надёжность

Ежедневное резервное копирование базы данных и загруженных файлов. Восстановление проверяется до запуска, а не после первой потери данных.

## 17. Этапы разработки

Порядок продиктован зависимостями: каждый следующий этап опирается на данные предыдущего.

**Этап 1. Основа.** Роли и вход, аккаунты, базовые данные, анкеты, политика ПДн и согласие при первом входе, программы, темы, материалы.

**Этап 2. Документы.** Публикация шаблонов, загрузка сканов, проверка администратором, приватное хранение файлов.

**Этап 3. Расписание — ядро системы.** Группы, закрепление преподавателей, формирование занятий, согласование преподавателем, публикация ученику, письма с расписанием, ссылки на занятия, отметка о проведённом занятии, учёт часов.

**Этап 4. Оплата.** Выставление счетов, платёжный сервис, статусы, история.

**Этап 5. Задачи и отчёты.** Интерактивные задачи по математике, отчёт по часам преподавателей, выгрузка.

Этап 3 — самый объёмный и самый рискованный: в нём вся логика состояний и согласований. Его стоит закладывать с запасом по времени.

Вне объёма текущего задания: интерактивные задачи по предметам, кроме математики; мобильные приложения; интеграция с бухгалтерией; электронная подпись договоров; уведомления в мессенджерах.
